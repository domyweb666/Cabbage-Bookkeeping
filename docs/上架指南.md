### 6. 找出金鑰和憑證的檔案

- 誰：多米，Claude 不經手，也不會去找這些檔
- 在哪裡：你當初存人蔘修煉那組檔案的資料夾；Key ID 在 App Store Connect → 使用者與存取權限 → 整合 → 團隊金鑰
- 做什麼：白菜記帳跟人蔘修煉用同一個 Apple 帳號，六個值可以放同一組。GitHub 存過的 secret 讀不回來，所以要找到原檔：
  1. API 金鑰的 `.p8`，檔名長得像 `AuthKey_XXXXXXXXXX.p8`。
  2. 發佈憑證的 `.p12`，人蔘修煉沿用的那張，還有它的密碼。
  3. 金鑰頁面上的 Key ID 和 Issuer ID。
- API 金鑰的角色要 App 管理（App Manager）。人蔘修煉那把就是，實際申請過描述檔、上傳過版本。Apple 的說明頁寫建立描述檔要帳號持有人或管理（Admin），App 管理要另外有「憑證、識別碼與描述檔」的權限；兩邊講的不完全一樣，所以先用那把，真的回 403 再換 Admin 的。
- `.p8` 找不到就建新的：按「+」，取名 `baicai-ci`，選 App 管理。有「存取憑證、識別碼與描述檔」的選項就勾。不用勾雲端簽章那個（Cloud Managed Distribution Certificate），手動簽章用不到。`.p8` 只能下載一次。
- `.p12` 找不到先跟我說，不要自己重做或撤銷憑證，別的 app 也在用。
- 檔案留在你當初存的資料夾，不要複製進 `E:\白菜記帳`，再備份一份。
- 算做完：兩個檔、一個密碼、兩個 ID 都在手上。

### 7. 放六個 GitHub secret

- 誰：多米
- 在哪裡：github.com/domyweb666/Cabbage-Bookkeeping → Settings → Secrets and variables → Actions
- 做什麼：六個都要放，名字跟人蔘修煉一樣，一個字都不能錯。

| 名字 | 內容 | 從哪裡拿 | 怎麼放 |
|---|---|---|---|
| `APPLE_DIST_P12_BASE64` | `.p12` 轉成的一長串 | 步驟 6 的 `.p12` | 指令 |
| `APPLE_DIST_P12_PASSWORD` | `.p12` 的密碼 | 你自己記的 | 貼 |
| `APPLE_TEAM_ID` | 10 碼 | developer.apple.com/account → Membership details → Team ID | 貼 |
| `ASC_KEY_ID` | 10 碼 | 步驟 6 的 Key ID | 貼 |
| `ASC_ISSUER_ID` | 有連字號，36 碼 | 步驟 6 的 Issuer ID | 貼 |
| `ASC_KEY_P8_BASE64` | `.p8` 轉成的一長串 | 步驟 6 的 `.p8`（直接貼檔案原文也吃） | 指令 |

兩種放法挑一種。指令都貼在 PowerShell，一次一行，路徑換成你自己的。

放法一，網頁貼上：按 New repository secret，Name 填名字，Secret 貼值，Add secret。兩個檔案要先轉成文字，下面的指令會把它放進剪貼簿：

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes('你當初存的資料夾\你的憑證.p12')) | Set-Clipboard
```

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes('你當初存的資料夾\AuthKey_XXXXXXXXXX.p8')) | Set-Clipboard
```

貼完把剪貼簿蓋掉：

```powershell
Set-Clipboard -Value ' '
```

有開 Win+V 剪貼簿歷程的話，到那裡把這兩筆刪掉。

放法二，用 `gh` 從檔案讀，不經過剪貼簿：

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes('你當初存的資料夾\你的憑證.p12')) | gh secret set APPLE_DIST_P12_BASE64 --repo domyweb666/Cabbage-Bookkeeping
```

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes('你當初存的資料夾\AuthKey_XXXXXXXXXX.p8')) | gh secret set ASC_KEY_P8_BASE64 --repo domyweb666/Cabbage-Bookkeeping
```

剩下四個，跑了會問你值，貼上去按 Enter。畫面不會顯示，命令列歷史也只留名字：

```powershell
gh secret set APPLE_DIST_P12_PASSWORD --repo domyweb666/Cabbage-Bookkeeping
```

```powershell
gh secret set APPLE_TEAM_ID --repo domyweb666/Cabbage-Bookkeeping
```

```powershell
gh secret set ASC_KEY_ID --repo domyweb666/Cabbage-Bookkeeping
```

```powershell
gh secret set ASC_ISSUER_ID --repo domyweb666/Cabbage-Bookkeeping
```

不要用 `--body` 把值寫在指令裡，那樣會留在歷史。路徑打錯會跳紅字，那個 secret 就沒有放進去，改好再跑一次。

放完看名字齊不齊，這個指令看不到值：

```powershell
gh secret list --repo domyweb666/Cabbage-Bookkeeping
```

- 算做完：清單有上面六個名字。這時候還不會出版，缺的話步驟 9 一按就紅，訊息會寫缺哪幾個。

## 現在要你決定／給的東西

照急的排。1 到 5 不給，TestFlight 出不來。其中 4、5 的檔案和登入只有你能動。

1. `.analytics` 閘門 2 資料結構：過，還是要改。閘門 0、1 一起回。
2. Bundle ID 用 `org.domyweb.baicai`，對不對。上傳後不能換。
3. （已定，2026-11-25）簽章走手動，你開口才出版。剩下的是讓改好的流程併進 `main`，你點頭就併。
4. 名字：先用「白菜記帳」，還是你有別的。副標、一句話介紹也要給。
5. 放六個 secret（步驟 7），建 App Group、兩個 App ID（步驟 4）和 App Store Connect 的 app，加自己進內部測試。
6. 聯絡信箱（隱私權政策、支援頁、意見回饋共用），和隱私權政策上的開發者名稱、生效日期。
7. 網址用 `domyweb.org/tools/baicai/` 那三頁，可不可以。
8. 審查聯絡人的姓名、電話、信箱，你自己在網頁填；版權那欄的名字。
9. 上架地區：推薦只上台灣，金額寫死新台幣，之後隨時可以加地區。另一個選法是照其他 app，拿掉中國大陸、其他全上。
10. 數位服務法的商家身分填了沒；沒填的話你是不是商家（你有賣課，這題我不幫你判斷）。
11. 類別財經加工具程式，版本號 1.0.0，條款用 Apple 標準合約，有不同意的再說。
12. 找一個沒看過 app 的人看截圖，再找一兩個真的在記帳的人試用。
13. AdMob（2026-11-27 加的橫幅廣告）：到 admob.google.com 用你的 Google 帳號開戶、填收款資料，新增一個 iOS app（白菜記帳），再建一個「橫幅」廣告單元。把 App ID（`ca-app-pub-…~…`）和橫幅單元編號（`ca-app-pub-…/…`）給我，我換進 `ios/project.yml` 的 `GADApplicationIdentifier`、`BaicaiBannerUnitID`。沒給之前，正式版和 TestFlight 都不出廣告，Debug 版用 Google 的測試廣告。
14. 有廣告之後，上架地區更建議只上台灣：上歐盟、英國的話，Google 要求先跳一個同意視窗（UMP），還要多做一輪。
