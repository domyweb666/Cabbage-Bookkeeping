# 開發中自行決定的事

規格沒寫到、或寫得不夠細的地方，我選了一個做法，記在這裡。有不同意的直接講，改起來都不大。

## 2026-11-25 改方向

多米決定拿掉引導、小白菜和 AI，改成手選金額與分類。方向是多米定的，下面 27 到 36 是做的時候我自己決定的事。

### 27. 資料改存手機，App 不連網路

沒有 AI 之後，雲端剩下備份的用途，卻要使用者建帳號，還要多米養一個後端。所以紀錄改用 SwiftData 存在手機，登入、Apple ID 綁定、同步都拿掉。代價是換手機要靠整機備份或裝置轉移，匯出的 CSV 也還不能匯入。AI 版沒上過 TestFlight，所以沒有寫舊資料搬家。

### 28. 分類編號固定，支出 12 類加收入 4 類

分類寫在程式裡，每一類有固定的編號，紀錄存編號，之後改名字不會影響舊紀錄。支出是飲食、交通、購物、日用、居住、娛樂、醫療、學習、訂閱、旅行、人情、其他；收入是薪水、獎金、投資、其他收入。使用者目前不能自己加分類。

（同一天稍晚改了：編號固定這點還有效；數量與自己加分類改成第 37、39 點，這 16 類變成預設顯示的。）

### 29. 標籤、商家、性質三欄合成備註和「一次性」

AI 版這幾欄有 AI 幫忙填，改成手填就太多了。現在剩一個可以不填的備註（最多 100 字）。性質原本分日常、一次性、固定，留下會影響比較的「一次性」，固定不另外標。

### 30. 明細最新在上

AI 版最新的在下面，因為輸入列在底部。現在記一筆是另外開一個畫面，最新的放上面，打開就看得到。

### 31. 改成三個分頁

記帳、分析、設定。舊規格把所有東西放在同一個主畫面，分析要點本月支出才進得去。分析頁的內容變多了，放在分頁列上比較找得到。

### 32. 後端檔案先留著

`supabase/` 和 `eval/` 沒有刪，App 沒有用到。後端測試搬到 `backend.yml`，設定成動到那兩個資料夾才跑。多米 2026-11-25 說先留著，不刪。

### 33. 本機資料庫打不開就直接顯示錯誤

畫面會寫「打不開紀錄」，不會默默改用記憶體。改用記憶體的話，使用者以為記好了，關掉就全部不見。資料庫打得開、但有紀錄讀不出來時，記帳、修改、刪除會停用，免得蓋掉還在的資料。分類的設定讀不出來也算在內，見第 39 點。

### 34. 修改留舊值，刪除先標記

改一筆時，改之前的類型、金額、日期、分類和一次性會留在同一筆裡；備註不影響數字，改了不留。刪除是加上刪除時間，提示條可以復原。畫面上目前沒有地方看舊值，提示條消失後也沒有地方把刪掉的找回來。真的刪掉要走「清除所有資料」。

### 35. 換日用午夜

半夜 12 點換日，沒有採用凌晨 4 點，因為紀錄要對得上發票和帳單上的日期。「今天」跟著手機的時區走。

### 36. 舊條目裡哪些作廢

- 1 到 13：App 沒有再用這份後端。檔案留著，條目當參考。
- 14：Supabase 那部分作廢，App 不再連網路。沒有第三方套件這點也變了，現在用一個多米自己的 VeggieKit，見第 47 點。
- 15：還有效。
- 16：還有效，現在沒有 entitlements 要產生。
- 17：Bundle ID 還有效，Apple 登入那半句作廢。
- 18 到 26：全部作廢。示範模式、離線排隊、回答卡、綁定 Apple ID、手機快取、引導、小白菜，還有 `-skipCoach`、`-forceCoach`、`-stillMascot` 三個啟動參數都不在了。畫面測試現在用的參數列在 `ios/AIFinance/App/AppConfig.swift`。

## 2026-11-25 畫面照準則改、分類可自訂

多米要的是：畫面照 `E:\多米ios開發準則` 改，分類和圖示加多，常用分類可以勾選、排序、自己取名。下面 37 到 50 是做的時候我自己決定的。準則逐條的對照在 `.uiux/準則對照.md`。

### 37. 內建分類支出 67、收入 17，編號只往後加

最早 16 類的編號（支出 1 到 12、收入 21 到 24）和名字一個都不動，舊紀錄靠它。後來加的支出從 101 起、收入從 201 起。以後只能往後加，不能改既有的編號和名字。「其他」永遠排最後。名字最多四個字，同一邊的圖示不重複，單元測試會檢查。沒動過設定的人，看到的還是那 16 類。

### 38. 「加油」叫「油錢」

「加油」在分析文案的禁用字裡，單元測試會拿每個內建分類組一次「記好了。」那句來掃。不想為一個名字開例外，所以叫油錢。使用者自己取的名字不掃，要叫「加油」也可以，備註也一樣。

### 39. 分類的設定整份存 SwiftData 一列

顯示哪些、順序、改過的名字、自己新增的，存成同一份 JSON。改了就存，沒有另外的儲存鈕；先寫進手機成功，畫面才變。讀回來會清一次：不認得的、重複的、已刪的、放錯邊的編號都拿掉，某一邊一個都不剩就回到預設的顯示。整份讀不出來時，跟紀錄讀不出來同樣處理，停用寫入。

### 40. 取名的規則

1 到 8 個字，前後空白去掉。同一邊（支出或收入）還在用的不能同名，沒勾的內建分類也算還在用；支出和收入之間可以同名。內建分類改名之後，原名還是留著不給別人用，恢復的時候才不會撞名。刪掉的自訂分類，名字可以再用。

### 41. 改名和換圖示不留舊值

內建分類改名存成一份覆蓋，編號不變；改回原樣就把覆蓋拿掉。紀錄只存編號，所以改名之後，以前的明細、分析和匯出全部用新名字，看不到當時叫什麼。

### 42. 刪除分類是標記，內建的不能刪

自己新增的才能刪，刪了標上時間。記過的紀錄照樣看得到名字，改那筆的時候也選得到，其他地方不能再選。刪掉之後沒有地方找回來。刪掉再取一個同名的，是兩個不同的分類，分析頁分開列。

### 43. 每一邊至少顯示一個

最後一個勾不掉，也刪不掉。

### 44. 取消勾選只影響格子

記過的不動，分析照列。改舊紀錄時，那一筆的分類沒勾或已刪，會補在格子最後面。記到一半去取消勾選已經選好的分類，回來就當作還沒選。

### 45. 找不到分類的紀錄歸「其他」，金額照算

紀錄上的編號對不到任何分類時，支出算在「其他」，收入算在「其他收入」。原本的編號留在紀錄裡不改。分析、分類明細、記完那一行和 CSV 都用同一個規則，總額跟各分類加起來才會一樣。

### 46. 恢復預設只動目前那一邊

切到支出就恢復支出的，收入不動。恢復的是顯示哪些、順序、內建的名字與圖示。自己新增的不刪，變成沒勾。按下去會先問一次。

### 47. 接 VeggieKit，設定頁只放真的能用的列

多了一個外部套件，多米自己的公開 repo，版本鎖在 1.0.1。信箱、隱私權政策網址、Apple ID 都還沒定，所以意見回饋、隱私權政策、評分、分享四列不出現。slug 先寫 `baicai`，一句話介紹先寫「按金額、點分類就記好一筆」，後者要有分享列才看得到。常用分類放在最上面，自己一組叫「記帳」。

### 48. 清除所有資料連設定一起清

分類、外觀、觸覺回饋都回到第一次打開的樣子，提示的文字也寫了「設定也會回到第一次打開的樣子」。

### 49. 自己加的三個顏色和震動表

設計系統沒有的三個顏色寫在 `Theme.swift`：收入的數字、停用按鈕的底、平常範圍那一段。停用按鈕沒用設計系統的 surfaceMuted，因為那個偏米色，在灰白底上看不出是按鈕。對比用 `design/contrast.py` 算。震動只有四種：記好或改好、沒存成、刪除、選分類或勾分類，表在 `Haptics.swift`。

### 50. 先照現在這樣做，等多米定

都列在 `.uiux/準則對照.md` 的「要多米定」。裡面跟操作有關的是這幾個：從修改畫面刪一筆會先問，左滑不問；記到一半按「取消」不問，往下滑會擋；從記一筆開的常用分類是疊上去的一張，從設定開的是往右推；常用分類直接做了一版，沒有先出比較頁。SwiftLint 在 CI 上先不擋，看過一輪再改。

## 後端（AI 版）

**1. entries 多了三種狀態和一個 result 欄位。**
規格 4.2 列的狀態是 committed、needs_confirm、answered、failed。我多加了 processing（處理中）、unclear（看不懂）、cancelled（使用者按了取消）。另外加 `result` 欄位，把第一次處理的結果原樣存下來，同一個 entry_id 重送時直接回這份，不用再呼叫 AI。

**2. profiles 多了 auto_commit_max。**
規格 7.7 的設定頁有「金額門檻」，但 4.1 的 profiles 沒有對應欄位，6.3 又說門檻是環境變數 AUTO_COMMIT_MAX。我的處理：使用者可以在 App 裡把門檻調低（1,000／3,000／5,000／10,000），存在 `profiles.auto_commit_max`；環境變數是上限，使用者設再高也不會超過它。

**3. 一句話裡只要有一筆需要確認，整句都走確認。**
規格 6.3 寫「全部成立才直接寫入」。「早餐 65，買電腦 45000」這種句子，兩筆會一起出現在確認卡，早餐那筆不會先偷偷入帳。這樣使用者看到的跟他講的是同一句，也不會有一半已經入帳、另一半被取消的狀況。

**4. 金額比對時，一個數字只能對一筆。**
「早餐午餐各 80」如果被解成兩筆 80，原話裡只有一個 80，第二筆對不上，走確認。中文數字（三百、3萬）不解析，一律走確認。

**5. 裝置時間如果在未來，用伺服器時間。**
離線補送時用的是手機記下的 client_created_at。手機時間被調到未來的話，「今天」會算錯，所以超過伺服器現在時間就以伺服器為準。

**6. 修正規則的學習寫在資料庫 trigger。**
使用者改分類（category_source 變成 user）時，trigger 用商家（沒有就用品項）建立或更新 user_rules。手動新增、在確認卡改分類也會學。這樣不管從哪個入口改，規則都會記到。

**7. 查帳的四個工具是資料庫函式。**
`q_sum`、`q_group`、`q_list`、`q_compare` 都是 security invoker，用呼叫者的身分跑，靠 `auth.uid()` 和 RLS 限定只查本人。Edge Function 先用白名單檢查模型給的參數，再把參數整包交給函式，不拼 SQL 字串。

**8. 回查只檢查寫成金額的數字。**
規格 6.4 要求回答中的金額都要出現在工具結果裡。我檢查的是 `NT$1,234`、`$1,234`、`1234 元` 這三種寫法。「11 月」「18 筆」這類數字不檢查，不然每個帶月份的回答都會被擋。沒通過就改回工具結果的制式摘要。

**9. 「依據」最多帶 200 筆交易編號。**
筆數超過時，回答卡仍顯示正確的總筆數，點開只列最近 200 筆裡手機上有的。

**10. 用量紀錄由 service role 寫。**
ai_usage 使用者只能讀。寫入由 Edge Function 用 service role 做，所以使用者沒辦法自己刪紀錄來繞過每日上限。

**11. 使用者只能軟刪除。**
transactions 沒有 delete policy。真的把資料刪掉只有一條路：設定裡的「刪除所有資料」，走 `delete_all_my_data()`。

**12. AI 模型與設定。**
供應商是 Claude。記帳解析用 `claude-haiku-5-5`，查帳用 `claude-sonnet-5-5`，都寫在環境變數，要換不用改程式。兩邊的 effort 都設 low，因為都是短任務，要的是快。查帳工具沒有開 strict 模式，參數由後端自己驗證。

**13. 測試裡的 AI 是照劇本回答的。**
規格 9.1 的案例測的是「模型給了這個答案之後，後端規則會怎麼處理」，所以測試用固定劇本，每次結果都一樣。真實模型答得準不準，由 `eval/run_eval.ts` 用 108 句另外量。

## iOS（AI 版）

**14. 沒有用 Supabase 的 Swift SDK。**
規格允許用，但我改成用 URLSession 直接呼叫 Supabase 的 HTTP API（登入、資料庫、Edge Function）。原因是開發機沒有 Mac，每多一個套件就多一份只能在 CI 上才知道會不會編譯的風險；App 用到的 API 也就十來個。結果是整個 App 沒有任何第三方套件。之後要換回 SDK，只要重寫 `SupabaseBackend.swift` 一個檔。

**15. 型別叫 TxCategory、Txn。**
`Category` 跟 ObjectiveC 的型別同名，`Transaction` 跟 SwiftUI 的同名，會編譯不過，所以換了名字。

**16. Xcode 專案檔由 XcodeGen 產生。**
`ios/project.yml` 是唯一的專案設定，`.xcodeproj`、`Info.plist`、entitlements 都在 CI 上產生，不進版控。在 Windows 上改設定只要改 yml。

**17. Bundle ID 先用 `org.domyweb.baicai`。**
要換的話改 `ios/project.yml` 的 `PRODUCT_BUNDLE_IDENTIFIER`，Supabase 的 Apple 登入設定也要跟著改。

**18. 沒設定雲端時是示範模式。**
建置時沒帶 SUPABASE_HOST 和 SUPABASE_ANON_KEY，App 會改用記憶體裡的假後端：可以記、可以問、可以確認，解析只是簡單規則，關掉就清空。CI 的畫面測試就是用這個模式跑。設定頁最上面會標明「示範模式」。

**19. 離線時問句也先排隊。**
規格 8.2 說離線不提供提問。但離線時 App 分不出一句話是記帳還是提問，所以一律先存原話，連線後送出，問句到那時才會得到回答。離線的說明文字有寫到這點。

**20. 回答卡集中放在時間軸最下面。**
規格 7.4 說回答卡出現在時間軸底部。交易照日期排，回答卡沒有混進日期裡，固定排在所有交易之後、輸入列上方，左滑可以移除。

**21. 綁定 Apple ID 的做法還沒實測。**
綁定是把 Apple 的 id token 送到 Supabase 的 `/auth/v1/token?grant_type=id_token`，帶 `link_identity: true`，掛到目前的匿名帳號上。如果這個 Apple ID 已經綁過別的帳號（換手機、重裝），而手機上還沒有任何紀錄，就改成直接登入那個帳號把資料取回；手機上已經有紀錄時不自動切換，改成提醒使用者先匯出。這段要等 Supabase 專案開好 Apple 登入、App 上了 TestFlight 才能驗證。

**22. 手機快取一次最多讀兩萬筆。**
時間軸讀的是手機上的快取，同步時分頁把所有未刪除的交易抓下來，上限 20 頁（每頁 1000 筆）。照 MVP 的用量很難碰到；真的碰到時，本月概覽的數字仍然正確，因為那是資料庫算的。

**23. 引導放在第一筆入帳之後，開場不放。**
規格 7.8 原本寫不做教學，驗收標準是開 App 到第一筆入帳 8 秒內。開場就跑引導會直接超過這個時間，而且那時畫面是空的，沒有東西可以指。所以改成記完第一筆、提示條消失後才出現，只講三個藏起來的操作：點一筆編輯與左滑刪除、點本月支出看概覽、長按送出鍵手動新增。已經有紀錄但沒看過引導的人，開 App 後也會看到一次。

**24. 引導目標的位置直接量全域座標。**
引導規格的做法是用 anchorPreference 把座標往上傳。時間軸是 List，列裡面的 preference 能不能傳到最外層，我在沒有 Mac 的情況下沒辦法確認，錯了就是第一步靜靜被跳過。所以每個目標改成自己量在螢幕上的位置，回報給 `CoachController`。遮罩蓋滿整個螢幕，座標可以直接用。

**25. 畫面測試多了兩個啟動參數。**
`-skipCoach` 讓引導不自動出現，原本的測試都帶這個，不然遮罩會擋住操作。`-forceCoach` 讓引導不管看過沒都出現，只有測引導的那個測試用。另外 `-stillMascot` 讓小白菜靜止，因為畫面測試每次操作前會等畫面停下來，一直在動的動畫可能讓它等到逾時。

**26. 記帳成功不放慶祝動畫。**
這個 App 的重點是記得快，每記一筆就跳一次會煩。小白菜的慶祝只留在引導第一步。
