# 開發紀錄

每個 Phase 完成後更新：做了什麼、測試結果、已知問題。

開發機是 Windows，沒有 Mac。後端測試和 iOS 的編譯、測試都在 GitHub Actions 上跑，下面寫的結果都來自 CI。

---

## Phase 0：打通建置線

**完成**

- `ios/project.yml`：用 XcodeGen 產生 Xcode 專案，App 與畫面測試兩個 target。
- `ios/Packages/FinanceCore`：只依賴 Foundation 的 Swift Package。
- DesignSystem：顏色（淺色、深色）、間距、卡片樣式集中在 `Theme.swift`。
- Supabase 本機環境：`supabase/config.toml`，開了匿名登入。
- `.github/workflows/ci.yml`：每次推送跑後端測試、FinanceCore 測試、App 編譯與畫面測試。
- `.github/workflows/testflight.yml`：封存並上傳 TestFlight。
- App 圖示：由 `design/AppIcon.svg` 轉成 1024 的 PNG。

**還沒做到的驗收**

規格的驗收是「空白 App 能從 Windows 推送後出現在 TestFlight」。編譯與測試這段已經通了；上傳 TestFlight 需要 Apple 的金鑰，workflow 寫好了但還沒實際跑過。要準備的東西在 `docs/SETUP.md` 第 3 節。

## Phase 1：後端核心

**完成**

- Migration：profiles、entries、transactions、categories、user_rules、ai_usage 六張表，全部啟用 RLS；12 個系統分類。
- `record`、`record/confirm`：先存原話，AI 回結構化結果，後端驗證後決定入帳或回草稿。同一個 entry_id 重送只處理一次。
- 規則：金額正規化與比對、直接入帳的七個條件、使用者修正規則覆蓋 AI 分類。
- 每日用量上限與用量紀錄。
- AI 供應商介面：Claude（`anthropic.ts`）與本機用的假供應商（`mock.ts`）。
- 評測：`eval/parse_cases.jsonl` 108 句，`eval/run_eval.ts` 算規格 1.5 的指標。

**測試結果**

| 測試 | 內容 | 結果 |
|---|---|---|
| `rules_test.ts` | 規格 9.2：金額正規化、金額是否在原話、日期範圍、筆數上限、規則覆蓋、AI 輸出驗證 | 21 過 |
| `db_test.ts` | 規格 9.4：RLS 隔離、金額不得小於等於 0、軟刪除不計入統計、復原後恢復、使用者分類不被覆寫 | 11 過 |
| `record_test.ts` | 規格 9.1 的 13 個案例，加上確認、取消、AI 失敗重試、每日上限、自訂門檻 | 23 過 |
| `smoke.ts` | 透過 HTTP 打本機 Edge Function：入帳、重送、草稿、確認、提問、未登入、超長 | 8 過 |

**還沒做到的驗收**

規格要求「評測達到 1.5 的指標」。評測腳本寫好了，也用假供應商確認流程能跑完，但真實模型的正確率要有 AI 金鑰才量得出來。假供應商只是關鍵字規則，它的分數沒有參考價值，所以這裡不列。

## Phase 2：記

**完成**

- 匿名登入：第一次開啟自動建立，session 存 Keychain，快過期自動換新。
- 主畫面：頂部本月支出、依日期分組的時間軸與每日小計、底部輸入列。
- 送出後輸入列立刻清空，可以連續記。
- 確認卡：半屏，每筆草稿一張小卡，顯示原因，金額、品項、分類、日期可改。
- 編輯畫面與手動新增（長按送出鍵）。
- 軟刪除與復原：左滑刪除、底部提示條 5 秒內可復原；剛入帳的也可以復原。
- 待送佇列：原話存在 SwiftData，離線時顯示「待處理」，恢復連線後依輸入順序補送，用當時記下的時間。

**測試結果**

- FinanceCore 單元測試：待送佇列狀態機（離線不送、依序送、失敗後重試、重開 App 後恢復）、時間軸分組與小計、金額格式、日期、後端回傳格式的解碼。（結果見文末「CI 結果」）
- 畫面測試：首次開啟到第一筆入帳、連續記帳與復原、確認卡、取消確認、看不懂的提示、編輯。

**還沒做到的驗收**

「實機上從開啟到入帳在 8 秒內，離線補送正確」要在 TestFlight 上量。離線補送的邏輯有單元測試，但真的切飛航模式這件事沒有在裝置上試過。

## Phase 3：語音

**完成**

- `SpeechService`：Apple Speech Framework，語系 zh-TW，辨識文字即時顯示在輸入框。
- 第一次按麥克風才詢問權限。
- 處理了權限被拒、辨識器不可用、麥克風啟動失敗、中途停止、超過 30 秒自動停止。
- 停止後文字留在輸入框可以修改；設定中可改成停止後自動送出。

**還沒做到的驗收**

語音完全沒有在裝置上跑過。模擬器沒有麥克風，CI 只確認了這段程式編譯得過。這是整個 App 裡最需要實機驗證的部分。

## Phase 6：聚光燈引導與小白菜

2026-11-15 加的，規格 7.8 同步改寫。

**完成**

- 吉祥物小白菜：戴白菜頭套的火柴人，用 SwiftUI 的 Canvas 畫，動作從網頁版的茄子火柴人動作庫移植過來。移了八個：待機、揮手、指向、思考、慶祝、聳肩、抓頭、鞠躬。程式在 `ios/AIFinance/Mascot/MascotView.swift`。
- 小白菜出現的位置：空畫面（揮手）、整理中的那一列（思考）、沒記成的那一列（抓頭）、概覽沒資料（聳肩）、引導的說明卡。
- 聚光燈引導：記完第一筆後出現一次，三步。程式在 `ios/AIFinance/CoachMarks/`，五個檔案。步驟內容只在 `CoachStep.swift` 的 `CoachTour.steps`。
- 設定頁加「重看教學」。
- 畫面測試加一個：記第一筆、引導出現、三步走完、從設定重看、跳過。

**跟引導規格不一樣的地方**

- 開場不自動出現，改成第一筆入帳後。理由寫在 `docs/DECISIONS.md` 第 23 點。
- 沒有分頁，所以步驟沒有「目標在哪個分頁」的欄位，也沒有切換分頁的程式。
- 目標位置用全域座標直接回報，沒有用 anchorPreference。見第 24 點。
- 說明卡換步驟是 0.18 秒交叉淡化，沒有做成「先淡出 0.12 秒再淡入 0.18 秒」兩段。
- 卡片背景用 App 的卡片色。系統背景色在深色模式是純黑，疊在變暗的畫面上會看不出卡片的邊。

**還沒驗證**

- 這些程式是在 Windows 上寫的，要等 CI 編譯和跑畫面測試才知道過不過。
- 動畫的手感、洞的位置準不準、VoiceOver、減少動態效果，都要上真機看。清單在 `docs/TESTFLIGHT_CHECKLIST.md` 的「引導與小白菜」。
- 白菜頭套是照 App 圖示的配色用程式畫的，沒有設計稿，實際好不好看要看截圖再調。

## 已知問題與限制

1. **還沒接真實服務。** Supabase 雲端專案、AI 金鑰、TestFlight 都還沒設定，App 目前只在示範模式下驗證過。
2. **真實模型的正確率沒量過。** 見 Phase 1。
3. **語音沒在裝置上跑過。** 見 Phase 3。
4. **綁定 Apple ID 沒實測。** 做法寫在 `docs/DECISIONS.md` 第 21 點。
5. **TestFlight 的簽章流程沒實際跑過。** 用的是自動簽章加 App Store Connect API Key。
6. **只支援單一裝置。** 規格 8.2 的假設。兩支手機登同一個帳號時，各自的快取要等回到前景才會更新。
7. **沒有做無障礙的完整檢查。** 主要按鈕有標籤，動態字級用系統字體，但沒有用 VoiceOver 實際走過一遍。
8. **本機 Docker 沒起來。** 這台 Windows 的 Docker Desktop 引擎啟動不了，所以需要資料庫的後端測試只在 CI 上跑過，沒有在本機跑過。

## CI 結果

2026-11-15，分支 `build-mvp`，GitHub Actions。

**後端**（ubuntu，本機 Supabase）

- Deno 測試：66 個全過（規則 21、資料庫 11、解析案例 23、查帳 11）。
- HTTP 冒煙測試：8 項全過。

**iOS**（macOS 15，Xcode 16.4，模擬器 iPhone Air／iOS 26.2）

- FinanceCore 單元測試：21 個全過。
- App 編譯成功。
- 畫面測試（示範後端）：9 個全過，每一步的截圖在該次執行的 Artifacts `ios-screenshots`。

**過程中抓到的問題**

- 第一次跑畫面測試時，「編輯」那個測試找不到今天的紀錄。看截圖才發現鍵盤升起後時間軸沒有捲到最底，最新的兩筆被擋住。這是 App 的問題，已修：鍵盤升完之後再捲一次。
- 深色模式的截圖一開始拍到的是淺色（測試在 App 開啟後才切換外觀）。後來發現模擬器的外觀設定在 CI 上切不動，改成由 App 的啟動參數 `-forceDark` 強制深色，並多拍確認卡與概覽。
